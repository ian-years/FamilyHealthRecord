# 个人健康档案工作台

把全家人的体检报告、化验单、发票、药盒归档成一份**结构化的、能看趋势的**本地健康档案。

数据全部落在你自己电脑的 `data\` 目录里，服务只监听 `127.0.0.1`，不需要登录、不需要账号、不需要装任何依赖。

> **本仓库不含任何真实病历。** 真实资料、真实姓名与体检编号、以及由它们派生的一切（数据库、附件、解析产物、跑真实数据时截的界面图）都在 `.gitignore` 里挡着，并且有可执行的入库自检盯着（见「隐私与数据边界」）。仓库里能看到的资料内容只有 `_fixtures\` 下自带「虚构测试数据」水印的合成资料。

## 它是什么，不是什么

是：资料的**归档、检索、趋势与费用统计**工具。七类资料一次归档，之后所有数字都能按人、按指标、按年份回看。

不是：不做诊断、不给治疗建议、不预测风险。系统里所有结论性文字都是从原报告**原文照录**并标注来源，不是本软件生成的判断。

## 快速开始

只需要 Python 3（本项目自己的启动器要求 3.8+，本机在 3.12.10 实测通过）。

| 平台 | 怎么做 |
| --- | --- |
| Windows | 双击 `启动本地工作台.bat` |
| macOS / Linux | `sh start.sh` |
| 手动 | `python server.py --port 8765` |

浏览器会自动打开 `http://127.0.0.1:8765/`（端口被占用时自动 +1，控制台会打印实际地址）。

想先看效果：进「上传资料」导入 `archive-package-fixture-report.json`（虚构的 3 页检验报告，24 项检验、含 OGTT 五点），概览页立刻就有能连线的指标。仓库里另有 `-receipt.json`（收费单）与 `-drug.json`（两枚药品）两个虚构归档包。

## 技术栈

- **后端**：Python 3 标准库，零第三方依赖（`http.server` + `sqlite3` + `urllib`）。没有 `requirements.txt` 可装，也没有虚拟环境要建。
- **数据**：SQLite 单文件（`data\health.db`）+ 附件原文件（`data\files\`）。12 张表，关系型模型 `persons → documents → indicators → observations`，外加别名、关注清单、收费明细、手填记录、药品与迁移日志。
- **前端**：原生 JS，**没有构建步骤**，没有框架、没有打包器。四个脚本按序加载：`localdb.js`（数据层）→ `logic.js`（纯业务逻辑）→ `app.js`（应用主体）→ `v2.js`（概览/详情/目录）。
- **Node.js** 只在跑测试时需要（`app\run-tests.js` 与浏览器端到端脚本），运行时不需要。

## 功能

侧栏六页：**数据概览 · 健康档案 · 上传资料 · 原始资料档案 · 药品管理 · 成员管理**。

- **七类资料归档**：挂号单/就诊单、检验报告、检查报告、体检报告、处方/用药单、医疗发票/收费单、其他医疗资料（末位兜底）。
- **按成员看数据**：概览顶部切换器（全部 / 各成员 / 未指定）。**指标定义全家共享一份，关注清单与趋势按人**——爸爸的血压不会出现在妈妈的趋势里。成员可改名、增删、调顺序；删成员不删档案，名下档案退回「未指定」。
- **指标趋势**：同义写法归一（`空腹血糖` / `血糖` 的别名与缩写），单位分裂自动合并（`g` 与 `mg/dL` 不并成一条线），参考范围随报告走。血压出双线，OGTT 出五点，血脂出分项组。
- **异常指标视觉区分**：超出原报告参考范围的行有独立标记，参考范围取的是那份报告自己印的值，不是内置标准。
- **费用统计**：按档案日期汇年度费用，发票/收费单明细单独入账。
- **手工编辑与留痕**：任何字段改过都留 from→to 历史，改错可回看是谁什么时候改的。
- **录入方式三条路**：① 解析桥（照片/PDF → 文字，需外部解析工具）② 大模型结构化（OpenAI 兼容协议，五个服务预设）③ **手动中转**——把提示词复制到任意大模型，再把返回的 JSON 粘回来，**不需要配任何密钥**，全程不出网。
- **备份与恢复**：导出单文件，**包含附件二进制**；恢复支持「只合并不覆盖」。任何不可逆操作前自动打快照（保留 20 份）。

## 隐私与数据边界

这不是一个可有可无的卖点，是这个项目的主要约束：

- 服务**只绑定 `127.0.0.1`**，局域网其他设备访问不到；无登录、无 cookie、无遥测。
- 浏览器端到端自测把整轮操作的外部请求数统计为 **0**（该脚本拦掉一切非 `127.0.0.1` 的请求并计数，结果记录在 `验收记录.md`）。唯二可能出网的环节是「解析」与「大模型结构化直连」，两者都可以完全不碰（用手动中转）。
- 出网前在本机做**脱敏**：姓名、身份证号、体检编号、单位名、医师姓名在请求发出前替换掉。
- 数据在磁盘上，不在浏览器里。**在浏览器点「清除浏览数据」不会丢任何档案。**
- 入库自检：`python _selftest/test_leak_tokens.py`（16 项）逐个扫描 git 跟踪的每一个文本文件，任何身份信息命中即失败；图片扫不到像素，所以另有一条白名单闸——**除 `_fixtures\` 的合成资料外，每张受跟踪图片必须在复核清单里逐张登记过**，新加一张没登记的就红。

```bash
         manual_observations observations_nullable indicator_links merge_backup; do
  python _selftest/test_$t.py

```

`test_server_routes.py` 会自己起一个连临时目录的服务子进程（占十几秒），不会碰真实数据。

浏览器端到端脚本 `_selftest\selftest.mjs`（231 条断言）**会清空所连服务的全部数据**，必须先用独立数据目录起服务：

```bash
HRW_DATA_DIR=./_selftest/data python server.py --port 8799 --no-browser &
cd _selftest && node selftest.mjs
```

> 本仓库提交时实测：静态守卫 3 条全绿、Node 自检 131 项、单位归并 12 项、Python 320 项全通过。浏览器端到端 231 条断言**本轮未跑**（需要本机 Chrome 与 `puppeteer-core` 目录联接，且它会清库），历史结果见 `验收记录.md`。

## 已知限制

完整清单在 `agent.md` §8（26 条），这里挑几条影响使用的：

- 概览的成员视图**不写 `localStorage`**，刷新后回到「全部」。记住「上次看的是妈妈」的代价是下次打开时全家数据凭空少一半，这类错乱比多点一次按钮贵。
- 趋势连线至少 2 个点，单点指标只显示最新值不画线。
- 写法不同就**不猜**：`餐后半小时` 与 `餐后 30 分钟` 保持分裂成两组。宁可少连一条线，不可把两个测量条件并成一条。
- 解析环节依赖外部工具，没装就只能在「上传资料」里手工填或走手动中转。
- 大模型直连默认未配置——这是有意的，手动中转始终可用。
